# LuminaEye 社区平台设计文档

## 1. 概述

本文档描述 LuminaEye AI 助盲眼镜项目从现有 landing page 扩展而来的社区平台应用设计。平台服务于两类用户：**盲人用户**（通过眼镜编号注册）和**志愿者**（通过邮箱注册）。

### 核心设计原则

- **零后端改动**：眼镜后端（`app_main.py`，`localhost:8081`）不做任何修改
- **静态导出**：继续使用 Next.js `output: 'export'`，整包静态托管
- **双角色隔离**：视频页面完全按角色隔离，论坛和地图共享
- **视障友好**：高对比度、大触控区域、屏幕阅读器支持、列表视图替代地图

## 2. 架构决策

### 技术栈

| 层级 | 技术 | 说明 |
|-----|------|------|
| 框架 | Next.js 16 App Router | 复用现有 landing page 项目 |
| 渲染 | 静态导出（`output: 'export'`） | 无服务端，纯客户端运行 |
| 样式 | Tailwind CSS 4 + globals.css | 延续 cyberpunk HUD design system |
| 动画 | Framer Motion | 复用现有动画模式 |
| 地图 | 高德地图 JS API | 免费额度充足，中文生态完善 |
| 状态 | localStorage + React Context | 无需服务端数据库 |

### 路由结构

```
app/
├── page.tsx                    # landing page（不变）
├── layout.tsx                  # 根 layout（不变）
├── globals.css                 # design system（不变）
├── sections/                   # 现有 8 个 sections（不变）
├── components/                 # 现有组件（不变）
│   └── ...
├── (app)/                      # 应用路由组（括号不进入 URL）
│   ├── layout.tsx              # 应用统一 layout（导航栏 + WebSocket）
│   ├── login/
│   │   └── page.tsx            # 登录/注册
│   ├── forum/
│   │   ├── page.tsx            # 论坛首页（帖子流）
│   │   └── post/
│   │       └── page.tsx        # 帖子详情（?id=xxx）
│   ├── video/
│   │   └── page.tsx            # 视频页面（角色差异化渲染）
│   └── map/
│       └── page.tsx            # 地图页面（高德地图）
```

### Landing → 应用跳转

`CTA.tsx` 注册按钮改为：
- 盲人用户：`<a href="/login?role=blind">`
- 志愿者：`<a href="/login?role=volunteer">`

## 3. 应用 Layout (`(app)/layout.tsx`)

### 职责

- **导航栏**：固定在顶部，角色差异化文案
- **全局 WebSocket**：连接 `ws://localhost:8081/ws_ui`，接收系统状态广播
- **角色上下文**：`React Context` 从 `localStorage` 读取 `lumina_role`
- **求助弹窗**：志愿者收到求助通知时弹出"接听/忽略"浮层

### 页面权限

- 未选择角色访问任何应用页面 → 重定向到 `/login`
- 所有应用页面共用 `(app)/layout.tsx`

## 4. 登录/注册页面 (`/login`)

### 整体布局

中央 HUD 风格卡片，复用 `HUDPanel` 组件（深色面板 + 青色边框发光 + 四角装饰线）。

### 角色切换（顶部 Tab）

两个大 Tab 按钮占据卡片顶部：
- **`👁 盲人用户`**（左侧，激活时边框变 `--color-lime` 绿色）
- **`🙋 志愿者`**（右侧，激活时边框变 `--color-cyan` 青色）

Tab 切换时下方表单有轻微滑动过渡动画（Framer Motion）。

### 盲人注册/登录（极简流程）

盲人用户**无需密码**，眼镜编号即唯一身份凭证。

| 字段 | 类型 | 说明 |
|-----|------|------|
| 眼镜编号 | text | 必填，格式 `GL-XXXX-XXX`。首次输入 = 自动注册，再次输入 = 直接登录 |
| 您的称呼 | text | 必填，用于论坛和视频中显示 |

**逻辑**：
- 输入眼镜编号后，前端检查 `localStorage` 是否已有该编号：
  - 不存在 → "首次使用，已为您注册" → 创建用户 → 跳转 `/forum`
  - 已存在 → "欢迎回来" → 跳转 `/forum`

**错误处理**：
- 编号格式错误 → "眼镜编号格式不正确"
- 编号为空 → "请输入眼镜编号"

### 志愿者注册/登录（标准流程）

| 字段 | 类型 | 说明 |
|-----|------|------|
| 邮箱 | email | 必填，格式校验 |
| 密码 | password | 必填，最少 6 位 |
| 您的称呼 | text | 必填 |
| 切换链接 | — | "已有账号？立即登录" / "没有账号？立即注册" |

**逻辑**：
- 注册：校验邮箱格式 → 检查邮箱是否存在于 mock 数据 → 创建用户 → 跳转 `/forum`
- 登录：校验邮箱+密码 → 匹配 mock 数据 → 跳转 `/forum`

**错误处理**：
- 邮箱格式错误 → "请输入有效的邮箱地址"
- 密码过短 → "密码至少需要 6 位"
- 登录邮箱不存在 → "该邮箱未注册"
- 密码错误 → "密码错误，请重试"

### 登录后状态

写入 `localStorage`：
```json
{
  "role": "blind" | "volunteer",
  "user": { "id": "...", "name": "...", "glassesId?" | "email?": "..." }
}
```

统一跳转到 `/forum`。

## 5. 导航栏设计

### 结构（从左到右）

| 位置 | 功能 | 说明 |
|-----|------|------|
| 左 | Logo / 返回首页 | 点击返回 landing page `/` |
| 中 | 核心导航 | 论坛、视频、地图（角色差异化文案） |
| 右 | 个人区 | 通知铃铛 + 角色标识 + 退出 |

### 角色差异化文案

| 页面 | 盲人看到 | 志愿者看到 |
|-----|---------|-----------|
| 论坛 | `社区论坛` | `社区论坛` |
| 视频 | `🆘 视频求助`（红色 pulse） | `视频协助`（带未接求助 badge） |
| 地图 | `附近帮助` | `援助地图` |
| 通知 | `求助状态` | `待接求助 (3)` |

### 快速状态条（Navbar 下方常驻细条）

- 盲人：显示眼镜连接状态（`🟢 眼镜在线` / `🔴 离线`）+ 当前位置
- 志愿者：显示当前在线盲人数量（`15 位盲人需要帮助`）

### 一键紧急入口（右下角悬浮按钮，独立于 Navbar）

- 盲人：大号红色按钮 `紧急求助`，点击直接发起视频求助
- 志愿者：不需要（通过视频页面接听）

### 无障碍细节

- `aria-current="page"` 标记当前页面
- `role="navigation"` + `aria-label="主导航"`
- 焦点状态：青色外发光（`outline: 2px solid var(--color-cyan)`）
- 每个按钮触控区域 ≥ 48×48px

## 6. 论坛 (`/forum`)

### 论坛首页布局

顶部：论坛标题 "Lumina 社区" + `+ 发布帖子` 按钮
中部：分类筛选 Tab
主体：帖子列表（卡片流）

### 帖子卡片设计（复用 HUDPanel）

- **左侧边框颜色标识角色**：盲人帖子 `border-l-4 border-lime`，志愿者帖子 `border-l-4 border-cyan`
- **作者行**：首字母头像 + 名字 + 角色标签小徽章
- **标题**：`text-lg font-bold`，单行截断
- **摘要**：`text-sm text-gray`，2 行截断
- **底部元信息**：评论数 💬 + 点赞数 ❤️ + 发布时间

### 分类筛选

4 个横向 Tab：
| 分类 | 说明 |
|-----|------|
| **全部** | 所有帖子 |
| **求助问答** | 盲人提问，志愿者或其他盲人回答 |
| **经验分享** | 使用心得、故事、建议 |
| **社区讨论** | 闲聊、活动、公告 |

### 发帖 Modal

HUD 风格弹窗：
- 标题输入框
- 分类选择（下拉）
- 内容文本域（最少 10 字）
- 发布按钮

**纯前端实现**：发帖后插入 mock 数据数组首位，同时写入 `localStorage`（页面刷新不丢失）。

### 帖子详情页 (`/forum/post?id=xxx`)

- 帖子完整内容（大标题 + 作者信息 + 正文）
- 点赞按钮（点击后 ❤️ 变红，计数 +1，写入 localStorage）
- 评论区列表（每条评论同样有角色颜色边框标识）
- 评论输入框 + 发送按钮

### Mock 数据规模

- **20 条帖子**：混合盲人（约 40%）和志愿者（约 60%）发布
- **每条帖子 3-8 条评论**
- **点赞数随机 0-50**
- 数据硬编码在 `app/(app)/forum/mock-data.ts`

## 7. 视频页面 (`/video`)

### 核心原则

同一个路由，根据 `localStorage.lumina_role` 渲染**两种截然不同的界面**，无任何切换入口。

### 盲人界面：求助发起端

```
┌─────────────────────────────────────────────┐
│  视频求助                                    │
├─────────────────────────────────────────────┤
│  ┌─────────────────────────────┐            │
│  │    [眼镜实时画面预览]          │            │ ← 连接 /ws/viewer
│  │    （连接中 / 实时画面）        │            │
│  └─────────────────────────────┘            │
│  🎙 语音指令已就绪                            │
│  对眼镜说"帮我找人"即可发起求助                │
│  当前状态：🟢 在线，等待求助中                │
│  [━━━━━━━ 手动发起求助 ━━━━━━━]              │ ← 备用按钮
└─────────────────────────────────────────────┘
```

**状态流转**：
```
空闲（在线）→ 语音触发 / 点击按钮 → 求助中（🟡 寻找志愿者...）→ 已连接（🟢 志愿者：小李）→ 通话结束 → 空闲
```

### 志愿者界面：求助接听端

```
┌─────────────────────────────────────────────┐
│  视频协助                           [通知🔔] │
├─────────────────────────────────────────────┤
│  ┌─────────────────────────────┐            │
│  │  求助者：小明（盲人用户）      │            │
│  │  眼镜：GL-2025-001            │            │
│  │  状态：🟢 实时连接中           │            │
│  │                             │            │
│  │      [实时视频流画面]         │            │ ← /ws/viewer
│  │                             │            │
│  └─────────────────────────────┘            │
│  [ 🔴 结束协助 ]  [ 🎙 语音开关 ]            │
│  ─────── 待接求助队列 ───────               │
│  🟡 小红  等待 2 分钟  [接听]               │
│  🟡 小刚  等待 30 秒   [接听]               │
└─────────────────────────────────────────────┘
```

### 求助弹窗（志愿者专属）

右下角弹出：
```
┌──────────────────────────────┐
│  🆘 新的视频求助              │
│  小明（盲人用户）发起求助      │
│  眼镜编号：GL-2025-001         │
│  [ 🟢 接听 ]   [ ⚪ 忽略 ]    │
└──────────────────────────────┘
```

伴随提示音，15 秒后自动消失。

### WebSocket 架构

| 连接 | 端点 | 用途 | 管理位置 |
|-----|------|------|---------|
| UI 状态 | `ws://localhost:8081/ws_ui` | 接收求助通知、系统状态 | `(app)/layout.tsx`（全局） |
| 视频流 | `ws://localhost:8081/ws/viewer` | 接收 binary JPEG 帧 | `/video` 页面（局部） |
| 音频流 | `http://localhost:8081/stream.wav` | 播放眼镜端环境音 | `/video` 页面（接听后） |

**降级策略**：如果 `localhost:8081` 未启动，前端进入 **Mock 模式**：
- 定时随机模拟求助通知（每 30-120 秒）
- 视频区显示占位动画（扫描线 + "等待眼镜连接"）

## 8. 地图 (`/map`)

### 整体布局

- 全屏高德地图
- 顶部：筛选 Tab（全部 / 盲人 / 志愿者 / 商家）
- 左下角：统计浮层（盲人 10 / 志愿者 20 / 商家 8）
- 右侧/底部：点击标记后的详情面板

### 三类标记设计

| 类型 | 颜色 | 图标 | 说明 |
|-----|------|------|------|
| **盲人/眼镜** | 🔴 红色 pulse 呼吸动画 | 眼镜图标 | 正在求助的盲人有红色外发光脉冲 |
| **志愿者** | 🔵 青色 | 人形图标 | 在线亮色，离线灰色 |
| **商家** | 🟡 黄色 | 店铺图标 | 提供就业岗位 |

### 信息窗体详情

**盲人标记**：姓名、眼镜编号、求助状态、位置、「导航前往」「视频协助」按钮

**志愿者标记**：姓名、在线状态、已帮助人数、「查看资料」按钮

**商家标记**：商家名称、提供岗位类型、地址、电话、「查看详情」「导航前往」按钮

### 盲人友好的列表视图（关键无障碍设计）

页面底部提供**可切换的列表视图**：

```
[🗺 地图视图]  [📋 列表视图]

列表视图：
┌─────────────────────────────────────┐
│ 🙋 志愿者小李  距离 300m  [求助]    │
│ 🙋 志愿者小张  距离 800m  [求助]    │
│ 🏪 阳光咖啡    距离 500m  [查看]    │
└─────────────────────────────────────┘
```

- 盲人默认进入列表视图（或地图+列表并列）
- 按距离排序，最近排在最前
- 每个条目有大点击区域

### Mock 坐标数据

以北京市中心（116.40, 39.90）为基准，随机偏移生成：
- 10 个盲人坐标
- 20 个志愿者坐标
- 8 个商家坐标

数据硬编码在 `app/(app)/map/mock-locations.ts`。

## 9. 数据流与状态管理

### localStorage 键值

| Key | 类型 | 说明 |
|-----|------|------|
| `lumina_role` | `'blind' \| 'volunteer'` | 当前用户角色 |
| `lumina_user` | JSON | `{ id, name, glassesId? / email?, role }` |
| `lumina_posts` | JSON | 用户发帖后的持久化帖子（补充 mock 数据） |
| `lumina_likes` | JSON | 用户已点赞的帖子 ID 数组 |
| `lumina_comments` | JSON | 用户发表的评论（补充 mock 数据） |

### React Context

- `RoleContext`：提供 `role` 和 `user`，全局可读
- `WebSocketContext`：管理 `/ws_ui` 连接，提供 `lastMessage` 和 `sendMessage`

## 11. 已知限制与假设

- **眼镜后端必须运行在 `localhost:8081`**，否则视频和通知进入 Mock 模式
- **静态导出限制**：无真实后端意味着发帖/评论/点赞数据仅在当前浏览器 session 内持久（`localStorage`）
- **视频流广播**：`/ws/viewer` 是广播端点，如多副眼镜同时运行，需后端支持路由区分（当前假设单眼镜演示场景）
- **坐标造假**：所有地图坐标为 mock 数据，不对应真实地理位置
